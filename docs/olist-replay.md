# Olist dataset replay

TraceGuard can replay anonymized order milestones from the [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce). Olist publishes the dataset under [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/). Use the dataset for the noncommercial class demo and keep attribution with any shared dataset derivatives. The CSV is loaded separately from the app.

| Source milestone | TraceGuard event |
|---|---|
| Order approved | `REGISTERED` |
| Order handed to carrier | `RECEIVED` |
| Order delivered to customer | `DELIVERED` |

The script selects delivered orders with all three milestones in chronological order. It uses a generated TraceGuard tag per selected order, a dedicated demo product and route, and three virtual checkpoints at the same location because the orders CSV has no scan coordinates. It treats the timezone-free source timestamps as UTC for replay. Checkpoint signatures are generated by TraceGuard during import. The dataset provides delivery milestones and supplies no RFID readings or counterfeit labels. Use the existing dev scenarios to demonstrate counterfeit detection.

## Run the replay

Download the dataset from Kaggle, extract `olist_orders_dataset.csv`, and use Python 3.11 or newer:

```bash
python scripts/replay_olist.py /path/to/olist_orders_dataset.csv --dry-run
python scripts/replay_olist.py /path/to/olist_orders_dataset.csv --email admin@traceguard.local
```

The second command connects to the local Vite app at port 5173 and prompts for the admin password. For the Docker stack, add `--url http://localhost:8080` and pass your configured admin address to `--email`. Pass `--limit` to choose the sample size (default 50), or `--replay-end-date YYYY-MM-DD` to move the latest delivery to noon UTC on a recent day while preserving time gaps. The script prints a generated tag you can open in Verify or the public consumer view.

You can rerun the same CSV, limit, and replay date to resume an interrupted import. Run one importer at a time. The generated batch and sorted tags provide a stable mapping, and existing timeline events must match the intended replay before the script appends any remaining events for that tag.

## Run the full app with Docker Compose

Create a local `.env` with values for `POSTGRES_PASSWORD`, `TRACEGUARD_JWT_SECRET` (at least 32 characters), `TRACEGUARD_ADMIN_EMAIL`, and `TRACEGUARD_ADMIN_PASSWORD`. Run from the repository root:

```bash
docker compose -f compose.deploy.yml up --build -d
```

Open [http://localhost:8080](http://localhost:8080). Compose starts the React frontend, Spring Boot backend, and PostgreSQL. It persists the database and checkpoint keys in separate named volumes. Use this stack separately from the existing database-only Compose file.

For a single-host AWS demo, the same Compose stack can run on EC2 or an Amazon Lightsail instance. Put a host HTTPS reverse proxy or an HTTPS load balancer in front of the frontend before public access. The default frontend binding is local to the Docker host, and the database and backend have no published ports.
